

AWS Lambda 從 2020 年底開始支援 **Docker 容器映像**（最大 10 GB），是一個非常省錢的選項，特別適合低流量的個人用途。

---

## 定價模型

Lambda 是**完全按用量計費**，沒有流量時 **$0 費用**。

| 資源 | 單價 |
|---|---|
| 請求次數 | $0.20 / 每 100 萬次請求 |
| 運算時間 (x86) | $0.0000166667 / GB-秒 |
| 運算時間 (ARM/Graviton) | $0.0000133334 / GB-秒（便宜 20%） |
| 暫時儲存 (>512MB) | $0.0000000309 / GB-秒 |

### 免費方案（每月，永久有效）

| 項目 | 免費額度 |
|---|---|
| 請求次數 | **100 萬次** |
| 運算時間 | **40 萬 GB-秒** |

### 月費估算（個人用途）

| 使用情境 | 記憶體 | 每日請求 | 平均執行時間 | 月費估算 |
|---|---|---|---|---|
| 極低流量 API | 512 MB | 500 次 | 200ms | **$0（免費額度內）** |
| 低流量網站 | 1 GB | 3,000 次 | 300ms | **$0 ~ $1 USD** |
| 中度使用 | 1 GB | 10,000 次 | 500ms | **$2 ~ $5 USD** |
| 較高流量 | 2 GB | 50,000 次 | 500ms | **$10 ~ $20 USD** |

## 搭配服務的額外費用

Lambda 通常需要搭配其他服務：

| 搭配服務 | 用途 | 費用 |
|---|---|---|
| **API Gateway (HTTP API)** | HTTP 端點 | $1.00 / 100 萬請求 |
| **API Gateway (REST API)** | 進階 REST 端點 | $3.50 / 100 萬請求 |
| **Lambda Function URL** | 免費 HTTP 端點 | **免費**（內建） |
| **ECR** | 存放容器映像 | $0.10 / GB / 月 |
| **CloudFront** | CDN / 前端靜態檔案 | 前 1 TB 免費 |
| **S3** | 前端靜態網站託管 | ~$0.023 / GB / 月 |
| **DynamoDB** | NoSQL 資料庫 | 25 GB 免費 |
| **RDS (PostgreSQL)** | 關聯式資料庫 | ~$13+ / 月 |

## 你的全端應用在 Lambda 上的架構

```
使用者
  ↓
CloudFront (CDN)
  ├── S3 → React 靜態檔案（前端）      ← 幾乎免費
  └── API Gateway / Function URL
        ↓
      Lambda (Docker) → FastAPI（後端） ← 按用量計費
        ↓
      DynamoDB 或 RDS（資料庫）
```

### 前端（React）
- `npm run build` 產生靜態檔案
- 上傳到 **S3** + **CloudFront**
- 費用：幾乎 **$0**（個人流量級別）

### 後端（FastAPI in Docker）
- 用 Lambda 容器映像跑 FastAPI
- 搭配 **Mangum** 這個 adapter 讓 FastAPI 跑在 Lambda 上
- 費用：低流量下 **$0 ~ $2 USD/月**

## Lambda 的限制（重要）

| 限制項目 | 數值 |
|---|---|
| 最大執行時間 | **15 分鐘**（不能跑長時間任務） |
| 容器映像大小 | **10 GB** |
| 記憶體 | 128 MB ~ 10,240 MB |
| /tmp 暫存空間 | 最大 10 GB |
| 同時並發數 | 預設 1,000（可申請提高） |
| 請求 payload | 6 MB（同步）/ 256 KB（非同步） |
| **Cold Start（冷啟動）** | 容器映像：**3 ~ 10 秒**（首次請求較慢） |
| WebSocket | 不直接支援（需搭配 API Gateway WebSocket API） |
| 持久化儲存 | **無**（必須用外部 DB/S3） |

### Cold Start 問題

這是 Lambda 最大的缺點。Docker 容器的冷啟動比一般 Lambda 更慢：

| 方式 | 冷啟動時間 |
|---|---|
| ZIP 包 (Python) | 0.5 ~ 2 秒 |
| Docker 容器 | **3 ~ 10 秒** |

**解決方案：**
- **Provisioned Concurrency**：保持實例暖啟動，但要 **$0.0000041667/GB-秒**（24 小時約 $3.6/月 per instance），失去省錢優勢
- **定時 ping**：用 CloudWatch Events 每 5 分鐘觸發一次，保持暖啟動（免費方案內）

## 適不適合你？

### Lambda 適合的情境
- API 請求不頻繁（每天幾百到幾千次）
- 可以接受偶爾 3-10 秒的冷啟動延遲
- 想要**不用的時候完全不花錢**
- 後端是純 API，不需要 WebSocket 或長連線
- 不需要跑背景排程任務（或用 CloudWatch Events 觸發）

### Lambda 不適合的情境
- 需要即時回應（冷啟動無法接受）
- 需要 WebSocket / 即時通訊
- 需要長時間運行的任務（超過 15 分鐘）
- 應用需要本地檔案系統持久化儲存
- 想用 `docker compose` 一鍵部署整套系統

## 最終建議

| 你的需求 | 推薦方案 |
|---|---|
| **最省錢、流量極低** | **Lambda + S3** → $0 ~ $2/月 |
| **省錢但要穩定回應** | **Lightsail** → $10/月固定 |
| **最靈活、完整控制** | **EC2 t3.small** → $16/月 |
| **跟在家自架一樣** | **EC2 + Docker Compose** |

對於你的全端應用（React + Python），如果流量真的很低且能接受冷啟動，Lambda 是**最省錢**的選擇。但如果你希望體驗跟本地開發一樣順暢，**EC2 + Docker Compose** 還是最直覺的方案。
